# Implementation Plan: adapters-package-extraction

> ★ **两处次序不可调换**：
> ① 守卫（任务 2）必须**先于**搬迁（任务 3）扩到四包 —— 源码直连 + 跨包导入使「搬错包」在类型层完全可能通过。
> ② 主入口收窄（任务 5）必须**后于**搬迁与接线 —— 它要基于**搬完后的真实导出面**重生成基准；
> 提前做只会得到一份中间态基准。

- [ ] 1. 基础：新包骨架与解析登记

- [x] 1.1 建立 adapters 包的清单与依赖面

  - 三个重依赖（云沙箱 SDK / 数据库驱动 / MCP SDK）**归此包**；另需内核 / 协议 / 日志 / 校验库
  - agent 运行时 SDK 两包声明为 **peer 且不标可选**（集合内有 7 处值导入）
  - ★ 通配导出**不可省** —— 它是依赖方向守卫看得见跨包深路径边的前提，漏了守卫会**永远绿**
  - 可观测完成态：工作区可见新包，且其清单里三个重依赖均在、agent SDK 在 peer 且无 optional 标记

- [ ] 1.2 建立新包的类型检查与分档测试基建
  - 以既有包的同名文件为样板建类型配置、测试配置、分档 workspace 与分档编排脚本
  - `tsconfig` 的 `rootDir` 取上一层（跨包引用内核源码否则触发 TS6059）
  - ★ 测试配置文件**必须存在**，否则静默继承仓库根配置，症状是「No test files found」
  - ★ 分档 workspace 的 setup 共享件跨包引用内核包对应文件；根级 setupFiles 在存在 workspace 文件时被**完全忽略**
  - ⚠ 测试搬入（3.2）前 fast 档必然为空、按设计就该失败 —— 本任务完成判据**不含** fast 档转绿
  - 可观测完成态：新包 `typecheck` exit 0；分档脚本可调起并明确报出「fast 档为空」
  - _Requirements: 6.4_

- [ ] 1.3 在全仓解析配置中登记新包
  - 仓库根测试配置加新包别名；★ 裸包名须用 **`$` 锚定的正则**且排在前缀条**之前**
    （字符串 alias 是朴素前缀匹配，带尾斜杠那条会把裸 specifier 一起吃掉）
  - 仓库根 fast / e2e 脚本串上新包，★ **排在末尾** —— 它在 3.2 前必然失败，排中间会短路掉后面的包
  - 确认服务端构建的别名表**不加**新包（走通配导出由解析器原生展开）
  - ★ **不要加裸包名 alias** —— 新包 `exports` 只有通配、没有 `"."` 主入口（任务 1.1 定的，与 File Structure Plan 一致）。
    加了会指向不存在的文件；上一轮教训：留着指向已搬走文件的 alias 比没有 alias 更难排查
  - 可观测完成态：仓库根测试面与类型检查均不因新包而失败（★ 根 `-r` 须排除 desktop，其为既有红）

## Implementation Notes

- 1.1：新包 `exports` **只有通配** `"./*.js": "./src/*.ts"`，无 `"."` 主入口 —— 未规划 `src/index.ts`，兼容层按深路径消费。⇒ 1.3 不得加裸包名 alias（会指向不存在的文件）。
- 1.1：刻意**不含** `scripts` 块（脚本要指向 1.2 才建的分档编排文件）。⚠ 静默性质：`pnpm -r run typecheck` 会**跳过**无该脚本的包，而根类型检查照样 exit 0 —— 1.2 须补上。
- 1.1：`devDependencies` 加了数据库驱动的类型包；agent SDK **未**误入 devDeps（否则直接触发 peer-only 守卫）。三个重依赖的版本与兼容层现声明**逐字一致**，为 5.2 的移除做对照基准。
- 1.1：新包依赖中**没有**工具包 —— 与 research.md 的 57 文件扫描一致（该集合零引用工具包）。这与 runner 包不同（runner 必须依赖工具包，内置扩展从那里来）。
