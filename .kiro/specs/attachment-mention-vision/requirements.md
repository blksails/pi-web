# Requirements Document

## Introduction

用户在对话里用 `@附件`（`@attachment:<id>`）引用本会话已落库的图片时，主对话模型（**native LLM**）
目前只能读到 `[attachment id=… type=… name=…]` 文本标记，看不到像素，因此无法直接识图。
新上传（拖拽/粘贴/选择）进输入框的图已经会作为**主模型多模态输入**喂给 native LLM；
`@` 引用与「仅附件 id」路径缺了这一步。

> **与 `image-vision-tool` 的定位分工（硬边界）**
>
> | | `image-vision-tool` | 本特性（native LLM 识图） |
> |---|---|---|
> | 谁看图 | 另选的视觉模型（委派 VLM） | **会话当前主模型本人** |
> | 形态 | 工具 / 命令（`image_vision`、`/img_vision`） | 用户消息的多模态图像输入 |
> | 何时用 | 主模型纯文本、省 context、专用 OCR 等 | 主模型本身支持看图，希望「像新上传一样」直接看 |
>
> 本特性**不是**扩展或改写 vision 工具；它是让 `@附件` / 已落库图像引用走与「composer 上传」
> **同一类**的 native 多模态通道，主模型本轮即可识图，**无需**先 `tool_call`。

本特性要求：当用户消息中通过 `@附件` 或等价的已落库附件引用指向**图像**附件时，
系统在提交给对话主模型前，把该图像内容一并物化为主模型可感知的**原生多模态图像输入**，
使 native LLM 直接识别，无需用户重新上传，也**不依赖** `image_vision` 工具调用。

## Boundary Context

- **In scope**：
  - 提交含 `@attachment:<id>` 的用户消息时，对**图像**附件向**对话主模型**提供原生多模态像素输入
  - 提交仅携带已落库附件引用（与 `@` 解析后等价）且引用为图像时，同样向主模型提供原生多模态像素输入
  - 与既有「文本引用标记」并存：工具仍能凭 `att_` id 解析附件（识图靠主模型，调 tool 靠 id）
  - 与既有「composer 上传即带图」路径兼容：同一请求不重复喂同一张图
  - 非图像附件、跨会话/未知引用的降级行为
- **Out of scope**：
  - **改写、扩展或依赖** `image_vision` / `/img_vision` 委派识别（那是独立工具能力；本特性不经过工具）
  - 为识图而新增「看图」类 agent 工具，或强制主模型先 tool_call 再得结论
  - 把图像字节写入对话历史文本或引用标记格式
  - 自动把会话历史中所有附件塞进每一轮上下文
  - steer / follow_up 忙时队列支持附件引用
  - 改变 tool result 的 base64 剥离闸门与「需复看」标记语义
  - 补全浮层缩略图、用户消息气泡内缩略图的新增展示（沿用既有能力）
  - 主模型是否支持图像输入的产品配置/拦截（与上传路径一致：能否看图取决于当前选用模型）
- **Adjacent expectations**：
  - **依赖**既有附件落库与按 id 读取内容的能力
  - **依赖**既有 `@` 补全与提交期 token 解析（attachment mention）
  - **依赖**既有 prompt **原生多模态**图像输入通道（与 composer 上传喂主模型的通道同类）
  - **不拥有**附件存储生命周期、签名分发、工具桥 resolve；**不替代**文本引用注入
  - **不拥有** `image-vision-tool`；两套能力可并存，职责不交叉

## Requirements

### Requirement 1: @附件图像对 native 主模型可见

**Objective:** As a 对话用户，I want 用 `@` 引用本会话的图片后**当前主模型本人**能直接看到该图，so that 我无需重新上传、也无需调用 vision 工具就能让 native LLM 识图。

#### Acceptance Criteria

1. When 用户提交的消息文本包含指向本会话**图像**附件的 `@attachment:<id>` 引用，the 消息提交链路 shall 使对话主模型在本轮以**原生多模态图像输入**收到该图像的像素内容，而不仅是文本引用标记。
2. When 用户提交的消息文本包含多个指向本会话图像附件的 `@attachment:<id>` 引用，the 消息提交链路 shall 使主模型在本轮收到这些图像的像素内容（顺序与引用在消息中出现的顺序一致）。
3. When 用户提交的消息文本包含 `@attachment:<id>` 且该附件为本会话**非图像**附件，the 消息提交链路 shall 不为该附件向主模型提供图像像素输入，并继续仅以文本引用标记呈现该附件。
4. The 消息提交链路 shall 在为主模型提供图像像素的同时，保留既有规范文本引用标记（含 id、类型、名称），使 agent/tool 仍能据此抄写附件 id。
5. When 上述图像引用被成功物化为原生多模态输入，the 消息提交链路 shall **不**为完成本轮识图而要求或触发 `image_vision`（或同类委派看图工具）调用。

### Requirement 2: 等价附件引用路径一致

**Objective:** As a 调用方（含 Web 以外的提交路径），I want 以已落库图像附件 id 提交的消息与 `@` 引用获得同等的**主模型原生**可见性，so that 不依赖客户端是否再传一份 base64、也不绕道 vision 工具。

#### Acceptance Criteria

1. When 用户消息通过已落库附件引用列表提交，且其中 id 指向本会话**图像**附件，the 消息提交链路 shall 使主模型在本轮以原生多模态图像输入收到对应像素内容（与 `@` 解析后的图像引用效果同类）。
2. When 同一请求中既有客户端已提供的图像输入、又有指向相同内容的附件引用，the 消息提交链路 shall 不向主模型重复附加同一图像的像素内容。
3. When 附件引用列表中的 id 未知或不属于当前会话，the 消息提交链路 shall 不为该 id 向主模型提供图像像素输入，且不阻断消息中其余有效内容的提交。

### Requirement 3: 失败与降级

**Objective:** As a 用户，I want 图像取回失败时对话仍可发送，so that 附件读取问题不会把整条消息卡死。

#### Acceptance Criteria

1. If 某图像附件的内容无法取回，then the 消息提交链路 shall 跳过该附件的像素输入，保留其文本引用（若可构造），并继续提交消息的其余部分。
2. If 消息中没有任何可物化为像素的图像附件，then the 消息提交链路 shall 保持与现状一致的纯文本（或既有客户端图像）提交行为，不引入额外失败。
3. The 消息提交链路 shall 不把图像字节写入用户消息的文本内容或规范引用标记字符串。

### Requirement 4: 与既有 native 上传识图路径兼容

**Objective:** As a 用户，I want 拖拽/粘贴新上传图片的 native 识图体验不被破坏，so that 日常发图行为零回归。

#### Acceptance Criteria

1. When 用户仅通过输入框附件区新上传图像并发消息（无 `@` 引用），the 消息提交链路 shall 继续使主模型以原生多模态输入收到这些图像的像素内容，行为与本特性引入前一致。
2. When 用户同时上传新图并 `@` 引用其它本会话图像，the 消息提交链路 shall 使主模型在本轮收到**全部**相关图像的像素内容（新上传与被引用的已落库图），且无重复。
3. The 消息提交链路 shall 不改变非图像文件附件的既有提交与文本引用行为。

### Requirement 5: 验证

**Objective:** As a 维护者，I want 有可重复的自动化验证，so that `@` 引用图像进入主模型原生多模态通道，且不依赖 vision 工具、上传路径不退化。

#### Acceptance Criteria

1. The 自动化测试 shall 验证：提交仅含指向图像附件的 `@attachment:<id>` 的消息时，主模型侧本轮 prompt 携带对应**原生图像输入**（像素存在，mime 与附件一致），而非仅文本标记。
2. The 自动化测试 shall 验证：提交指向非图像附件的 `@attachment:<id>` 时，主模型侧本轮不因该附件获得图像像素输入，且文本引用仍存在。
3. The 自动化测试 shall 验证：客户端已带图像输入且同时带相同附件引用时，主模型侧不出现重复图像输入。
4. The 自动化测试 shall 验证：既有「composer 上传图像喂主模型」路径在本特性下不发生行为退化。
5. The 自动化测试 shall 验证：上述 `@` 图像物化路径**不**以调用 `image_vision` 工具作为识图前提（无强制 tool_call 才能看图）。
