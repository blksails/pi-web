# Implementation Plan

## 1. 压缩纯函数

- [x] 1.1 实现图片压缩的判定与短路逻辑 (P)
  - 依据体积阈值决定是否压缩；未达阈值原样返回
  - 动图与矢量图一律跳过，保持原文件
  - 运行环境不具备图像解码能力时直接放行
  - 完成条件：上述三类输入均返回与入参**同一个**文件对象，且全程未触碰解码接口
  - _Requirements: 1.5, 3.2, 3.3, 4.2_
  - _Boundary: 附件预处理层_

- [x] 1.2 实现解码与重绘（方向保真 + 白底）
  - 解码时应用原图的方向标记，使输出的视觉方向与原图一致
  - 重绘前以白色填充背景，避免透明区域转为纯色格式后变黑
  - 默认保持原始像素尺寸；仅当长边超过极端上限时等比缩放
  - 用完立即释放解码资源，不等待垃圾回收
  - 完成条件：解码调用带方向选项、绘制前有白底填充，二者均可被测试断言
  - _Requirements: 1.3, 1.4, 2.1, 2.2, 2.3, 3.1_
  - _Depends: 1.1_
  - _Boundary: 附件预处理层_

- [x] 1.3 实现编码、体积比较与失败回退
  - 优先使用可将编码移出主线程的画布实现，不可用时降级到常规画布
  - 编码为有损格式，文件名与类型同步更新
  - 编码结果不小于原图时保留原图
  - 任何环节抛错一律捕获并返回原图，函数对外永不抛出
  - 完成条件：成功路径产出新文件；构造解码失败与体积反增两种情形，均得到原文件且无异常逃逸
  - _Requirements: 1.2, 3.4, 4.1, 4.3_
  - _Depends: 1.2_
  - _Boundary: 附件预处理层_

- [x] 1.4 补齐压缩纯函数的单元测试
  - 覆盖阈值短路、动图/矢量跳过、环境缺失、解码失败、体积反增五条回退路径
  - 以调用契约断言方向选项与白底填充确实发生（此二者属不可回归的硬约束）
  - 覆盖不缩放与超限缩放两种尺寸分支
  - 完成条件：测试全绿，且删除方向选项或白底填充任一处会导致对应用例失败
  - _Requirements: 1.2, 1.3, 1.4, 1.5, 2.1, 2.2, 3.1, 3.2, 3.3, 3.4, 4.1, 4.2, 4.3_
  - _Depends: 1.3_

## Implementation Notes

### 真机 e2e 证据(2026-07-28,真实 Chromium + 真实源码 + 用户提供的真实照片)

以 esbuild 把 `compress-image.ts` 原样打包注入 Chromium,喂 4 张真实临床照片(存为 PNG):

| 文件 | 压缩前 | 压缩后 | 降幅 | 耗时 |
|---|---|---|---|---|
| …1805 | 748KB | 101KB | -86% | 32ms |
| …1806 | 803KB | 80KB | -90% | 12ms |
| …1807 | 964KB | 104KB | -89% | 12ms |
| …1808 | 751KB | 86KB | -89% | 12ms |
| **合计** | **3.19MB** | **0.36MB** | **-89%** | — |

★闭环成立:压缩前合计 3.19MB **会被** Req 7 的 payload 上限拦截;压缩后 0.36MB **落入安全区**。
短路路径真机确认:小图与 GIF 均返回原对象未被触碰。

### 5.2 真实浏览器长任务观测(已完成)

以 `PerformanceObserver({entryTypes:["longtask"]})` 在真实 Chromium 中观测**批量**压缩:
12 张真实照片(4 张 × 3 副本)经**真实 `mapWithLimit`(并发 3)**驱动 —— 与 `use-attachments`
中的接线一致。

| 指标 | 结果 |
|---|---|
| 体积 | 9.57MB → 1.09MB(-89%) |
| 总耗时 | 4105ms(12 张,并发 3) |
| 全部转码 / 保序 | ✅ / ✅ |
| **主线程长任务(>50ms)** | **零** |

★零长任务证实了设计判断:`OffscreenCanvas.convertToBlob` 确实把编码移出主线程,
故批量压缩期间界面保持可交互(Req 5.4 达成)。

注:批量下均摊 342ms/张,显著高于单张直测的 12–32ms —— 并发竞争与调度开销所致;
但由于不占主线程,对交互无影响。

**未覆盖**:完整 UI 拖拽路径未走通 —— dev 页面有登录墙(`feat(identity)` 的
「暂不登录」出口已于 62ea71fe 被 Revert),无法进入聊天界面实拖。本测试直接驱动
生产代码路径(compressImage + mapWithLimit),覆盖了 5.4 的实质关切。

### 实现要点留痕

- 阈值 200KB、上限 1.5MB 均为常量,前者取激进档(用户决策),后者职责是「兜住必然失败者」而非精确划线。
- `checkPayloadLimit` 从 `run-image-tool.ts` 导出仅为可测性;运行时唯一调用点在 `resolveMediaFields` 之后。
- 并发取 3:单张 4000×3000 位图约 48MB,3 路并行足以掩盖单张延迟又不撑爆内存。
