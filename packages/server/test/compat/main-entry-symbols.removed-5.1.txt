# 主入口 adapters 转发面 —— 移除清单(spec: adapters-package-extraction,任务 5.1;R3.2 / R3.3)
#
# 这是一次**有意的破坏性契约变更**:`packages/server/src/index.ts` 移除了 8 条
# `export * from "@blksails/pi-web-adapters/<模块>/index.js"`(extensions / tokens / auth /
# llm-gateway / ai-gateway / identity / sandbox-transport / session-store-postgres)。
#
# ★ 本文件存在的唯一理由:「有意移除」与「不小心弄丢」在 diff 上长得一模一样。
#   数量差回答不了「少的是哪几个」—— 下面逐一枚举,共 161 个符号
#   (89 个运行期值 + 72 个纯类型)。
#
# 格式:`<原转发模块>` TAB `<符号名>` TAB `<value|type-only>`,一符号一行;`#` 开头为注释。
# 消费方迁移路径:改从 `@blksails/pi-web-adapters/<原转发模块>/index.js` 深路径导入。
#
# ★★ 为什么必须分 value / type-only 两类 —— 一条**容易踩空的**事实:
#   常驻基准 `main-entry-symbols.txt` 是 `Object.keys(await jiti.import(...))` 的产物,
#   **只看得见运行期值**。故那份基准记录的收窄是 313 → 224(差 89 个值),
#   而真实的契约损失是 161 个 —— 另外 72 个纯类型在基准里**从来没出现过**,
#   它们消失时基准一声不响。跨仓消费方的 `tsc` 会照样报红(本仓实测:AiGatewayConfig /
#   EgressModel / LlmGatewayProviderTable 等就是这样暴露的)。⇒ 只读符号基准会**低估**本次变更。
#
# ⚠ 有 5 个符号**不在**本清单里,因为它们同时由内核包导出、经 `export * from
#   "@blksails/pi-web-core"` 仍在主入口上,不属于被移除:
#     session-store-postgres/{SessionStoreConfig, SessionStoreKind, sessionStoreConfigFromEnv}
#     ai-gateway/{GatewayModelEntry, ModelPrecedence}
#   ⇒ 8 个模块导出并集 166 个,减去这 5 个 = 本清单 161 个。
#
# 收窄前的完整 313 值符号基准另存为 `main-entry-symbols.before-adapters-extraction.txt`(可考古)。
# 收窄后由 `main-entry-symbols.txt` + `main-entry-symbols.it.test.ts` 继续以「逐字相同」把关(R3.4)。
